User prompt: Is there something that allows jev to classify user input to restrict the intent drift from system 2 models
Response: It appears that several patterns and framework implementations use TypeSafe Jev as an intent classifier and guardrail to restrict intent drift from System 2 (generative/reasoning) models. Because System 2 models are prone to open-ended instruction drift and hallucination, Jev is deployed as a fast (~100ms) pre-execution gate or mid-loop trajectory validator.
Key Mechanisms
1. Jev Intent Classifier / Router (Choice Primitive) Frameworks like the LangChain Jev Harness and n8n Jev Router evaluate incoming user prompts through Jev before calling the System 2 model. Jev scores the input against pre-defined intent buckets (e.g., ["coding", "database", "out_of_bounds"]) and emits a probability distribution. If the input classifies as out_of_bounds, the System 2 model is never invoked.
2. Probability & Confidence Thresholding (jevcal) Unlike standard LLMs, Jev returns explicit confidence scores alongside its predictions. Architectures leverage calibration tooling like jevcal to enforce hard confidence thresholds (e.g., p<0.85), routing low-confidence or ambiguous inputs to safety fallbacks rather than allowing a System 2 model to make ungrounded inferences.
3. Tool & State Approval Gates (e.g., Vercel eve) In agentic loops, middleware such as Vercel's eve passes proposed System 2 actions into Jev to classify them as clear vs. caution prior to execution. This restricts System 2 models from drifting into unintended tool usage or modifying state out of turn.
Operational Doubts & Limitations
* Edge-Case Misclassification: Early benchmarking indicates Jev may over-classify out-of-domain or nuanced prompts into broad "other" or false-positive categories more frequently than larger reasoning models.
* No Semantic Context Repair: While Jev can reject or reroute a drifting prompt, it cannot reformulate or repair ambiguous user context on its own.
* Context Truncation Risk: Evaluating long multi-turn conversations against broad intent schemas may hit Jev's context ceilings, necessitating lossy state truncation prior to classification.

Response: To enforce high-probability intent capture and prevent System 2 coding models (such as those driving OpenCode) from drifting, you can implement a two-sided Jev sandwich architecture:
1. Pre-Execution (Intent Capture & Calibration): Formats user input, routes it via jev-classifier, validates confidence via jevcal, and forces a clarification dialogue if ambiguity exceeds a strict threshold.
2. In-Loop Trajectory Gate (eve + OpenCode Hooks): Locks down the captured spec and intercepts every OpenCode tool execution via tool.execute.before to verify that proposed changes remain within bounds.
Phase 1: Structuring Inputs to be "Jev-Friendly"
Free-form, open-ended text leads to high variance in System One classification. Jev performs best when evaluating discrete state objects with explicit keys rather than parsing unformatted prose.
Instead of feeding raw prompts directly, pass input through a Structured Intent Schema:
{
 "intent_manifest": {
   "action": "refactor | feature | bugfix | chore",
   "target_scope": ["src/controllers/auth.ts"],
   "acceptance_criteria": ["Replace JWT verification with HMAC session check"],
   "non_goals": ["Do not touch database schema", "Do not modify user routes"],
   "raw_prompt": "Replace JWT with HMAC in auth controller, leave DB untouched"
 }
}

Enforcing the Structure
* CLI Pre-Flight Wrapper: Before invoking OpenCode, run a lightweight prompt template (e.g., using gum or Inquirer.js) to capture action, scope, and non_goals interactively.
* Jev Pre-Parser: If starting from raw text, use a fast Jev extraction pass to normalize the input into the intent_manifest JSON schema before downstream evaluation.
Phase 2: Pre-Execution Intent Guardrail (jev-classifier + jevcal)
Before OpenCode initializes its System 2 loop, evaluate the intent_manifest against Jev's Choice and Noul primitives.
import { JevClient } from "@typesafe/jev";
import { jevcal } from "jevcal";

const jev = new JevClient({ apiKey: process.env.JEV_API_KEY });

async function validateUserIntent(manifest: object) {
 // 1. Evaluate Intent & Ambiguity in a single parallel pass
 const response = await jev.evaluate({
   state: manifest,
   questions: {
     intent_category: {
       type: "Choice",
       options: ["refactor", "feature", "bugfix", "out_of_scope"]
     },
     is_unambiguous: {
       type: "Noul",
       statement: "The target scope and acceptance criteria are fully specified and safe to execute automatically."
     }
   }
 });

 // 2. Pass probabilities through jevcal to get calibrated confidence
 const calibratedConfidence = jevcal.calibrate(response.questions.is_unambiguous.probability);
 const selectedChoice = response.questions.intent_category.winner;

 // 3. High-probability decision gate
 if (calibratedConfidence < 0.92 || selectedChoice === "out_of_scope") {
   return {
     status: "CLARIFY_WITH_USER",
     reason: `Low confidence (${(calibratedConfidence * 100).toFixed(1)}%). Please specify exact files or acceptance criteria.`
   };
 }

 return { status: "PROCEED", manifest };
}

If status === "CLARIFY_WITH_USER", execution halts immediately and prompts the developer for targeted input rather than handing an ambiguous prompt to OpenCode.
Phase 3: Preventing Execution Drift (eve + OpenCode Tool Hook)
Once an intent is validated, lock down the intent_manifest as an immutable invariant for the session. Use Vercel's eve tool-approval patterns integrated directly into OpenCode's plugin API.
Create an OpenCode plugin (.opencode/plugins/intent-guardrail.ts) that intercepts tool calls before execution:
// OpenCode Plugin: .opencode/plugins/intent-guardrail.ts
import { JevClient } from "@typesafe/jev";

const jev = new JevClient({ apiKey: process.env.JEV_API_KEY });
let lockedManifest: any = null;

export const intentGuardrailPlugin = {
 // Store validated intent on session start
 "session.start": async (context) => {
   lockedManifest = context.sessionStorage.get("intent_manifest");
 },

 // Intercept every tool action before OpenCode executes it
 "tool.execute.before": async (input, output) => {
   const proposedAction = {
     tool: input.tool, // e.g. "bash", "write_file", "edit_file"
     params: input.args, // e.g. { path: "src/db/schema.ts", content: "..." }
   };

   // Evaluate proposed tool call against the locked manifest
   const result = await jev.evaluate({
     state: {
       manifest: lockedManifest,
       proposed_action: proposedAction
     },
     questions: {
       aligns_with_intent: {
         type: "Noul",
         statement: "Does this specific tool action strictly align with the target scope and acceptance criteria without violating non_goals?"
       }
     }
   });

   // Block action if intent drift is detected
   if (result.questions.aligns_with_intent.probability < 0.95) {
     throw new Error(
       `[INTENT DRIFT BLOCKED] Proposed tool call '${input.tool}' on '${JSON.stringify(input.args)}' ` +
       `strayed from locked intent non-goals/scope.`
     );
   }
 }
};

Component Breakdown & Technical Nuances
1. Schema Normalization Engine
* Execution: Converts free text into a constrained intent_manifest JSON schema prior to evaluation.
* Hypothesized Risk: Automated normalization passes using LLMs or extraction templates may inadvertently introduce hallucinated constraints or strip out subtle edge-case requirements specified by the user.
2. Pre-Execution Calibration Node (jev-classifier + jevcal)
* Execution: Evaluates the manifest against two parallel System One queries:
   1. Pcategory​=Jev.Choice(options=["refactor","feature","bugfix","out_of_bounds"])
   2. Punambiguous​=Jev.Noul("Target scope and criteria are fully bounded")
* Calibration: Pcal​=jevcal.calibrate(Punambiguous​).
* Hypothesized Risk: It is uncertain whether static calibration curves in jevcal generalize across highly heterogeneous codebases without requiring domain-specific fine-tuning datasets.
3. In-Loop Trajectory Interceptor (eve Plugin)
* Execution: Hooks directly into OpenCode's execution lifecycle (tool.execute.before). Each proposed command Ti​ (e.g., file edits, terminal execution) is validated via Jev against the locked manifest:
Palign​=Jev.Noul("Proposed action Ti​ strictly adheres to non-goals and target scope")
* Hypothesized Risk: Multi-step refactoring workflows may suffer from false-positive blocks if an intermediate step appears to violate end-state criteria before reaching final completion.

	OpenCode Event / Lifecycle Hook
	Mechanism Inside OpenCode
	1. Input Text
	chat.message
	Intercepts incoming user input before it reaches the main LLM context.
	2. Interactive Schema Normalization
	chat.message + ctx.ask()
	Extracts candidate JSON via Jev/LLM parser, then uses OpenCode's TUI modal (ctx.ask) to prompt the developer to finalize fields (target_scope, non_goals) directly in the terminal.
	3. Pre-Execution Classifier & jevcal

	4. Locked Manifest Context

	5. System 2 Execution Loop
	Native OpenCode Prompt Engine
	OpenCode reasoning LLM plans and proposes tool actions (Ti​).
	6. Trajectory Interceptor
	tool.execute.before
	Intercepts every tool call (e.g., bash, edit_file) before execution. Evaluates Ti​ against locked_manifest.json using Jev.Noul.
	7. Execution / Fallback

import { Plugin } from "@opencode-ai/plugin";
import { JevClient } from "@typesafe/jev";
import { jevcal } from "jevcal";

const jev = new JevClient({ apiKey: process.env.JEV_API_KEY });

export const JevGuardrailPlugin: Plugin = async (ctx) => {
 let lockedManifest: Record<string, any> | null = null;

 return {
   // Stage 1 - 3: Intercept Prompt & Interactive Normalization
   "chat.message": async (input, output) => {
     const rawPrompt = output.parts.find((p) => p.type === "text")?.text;
     if (!rawPrompt) return;

     // Extract preliminary candidate schema
     const candidate = await jev.extractSchema(rawPrompt);

     // Interactive TUI prompt inside OpenCode
     const userApprovedScope = await ctx.ask({
       question: "Confirm target scope for this task:",
       default: candidate.target_scope.join(", "),
     });

     const manifest = {
       ...candidate,
       target_scope: userApprovedScope.split(",").map((s) => s.trim()),
     };

     // Pre-execution Jev evaluation
     const res = await jev.evaluate({
       state: manifest,
       questions: {
         is_unambiguous: {
           type: "Noul",
           statement: "The task scope and non-goals are completely unambiguous.",
         },
       },
     });

     const pCal = jevcal.calibrate(res.questions.is_unambiguous.probability);

     if (pCal < 0.92) {
       throw new Error(
         `[JEV GUARDRAIL] Ambiguous intent detected (${(pCal * 100).toFixed(1)}%). Please refine non-goals or scope.`
       );
     }

     // Stage 4: Lock state for session
     lockedManifest = manifest;
     await ctx.storage.set("locked_manifest", manifest);
   },

   // Stage 6 - 7: Intercept Tool Execution
   "tool.execute.before": async (input, output) => {
     if (!lockedManifest) return;

     const proposedAction = { tool: input.tool, args: output.args };

     const evalRes = await jev.evaluate({
       state: { manifest: lockedManifest, proposedAction },
       questions: {
         aligns: {
           type: "Noul",
           statement: "Does this tool execution strictly align with locked target_scope and non_goals?",
         },
       },
     });

     const pAlign = evalRes.questions.aligns.probability;

     if (pAlign < 0.80) {
       throw new Error(`[JEV DRIFT BLOCKED] Action violates locked non-goals.`);
     } else if (pAlign < 0.98) {
       // Fallback to OpenCode permission prompt
       const approved = await ctx.ask({
         question: `[JEV BORDERLINE (${(pAlign * 100).toFixed(1)}%)] Approve '${input.tool}' execution?`,
       });
       if (!approved) throw new Error("User denied borderline tool execution.");
     }
   },
 };
};

Operational Doubts & Technical Caveats
   * Hook Dispatch Latency: There is significant doubt regarding whether async calls inside tool.execute.before introduce noticeable lag during large, fast multi-tool refactoring runs.
   * TUI Input Blocking: It remains dubious whether nested ctx.ask modal interactions inside chat.message work reliably across all terminal multiplexer setups without breaking message context rendering.
   * State Persistence Across Crashes: If the OpenCode process restarts mid-session, relying on in-memory lockedManifest state may fail unless explicitly backed by project-level disk storage (.opencode/state/locked_manifest.json).

import { Plugin } from "@opencode-ai/plugin";
import { JevClient } from "@typesafe/jev";
import { jevcal } from "jevcal";
import * as fs from "fs/promises";
import * as path from "path";

const jev = new JevClient({ apiKey: process.env.JEV_API_KEY });

export const JevTuningPlugin: Plugin = async (ctx) => {
 const tracePath = path.join(ctx.location.directory, ".opencode/state/traces.json");
 const configPath = path.join(ctx.location.directory, ".opencode/state/jevcal_config.json");

 return {
   // Expose /jev-tune as an explicit command/tool
   tool: {
     "jev_tune": {
       description: "Run interactive calibration pass over saved session traces",
       args: {},
       async execute(args, context) {
         // 1. Load recorded traces from disk
         const rawData = await fs.readFile(tracePath, "utf-8").catch(() => "[]");
         const traces = JSON.parse(rawData);

         if (traces.length === 0) {
           return "No execution traces found. Run a few guarded OpenCode sessions first.";
         }

         const dataset: Array<{ rawProb: number; label: 0 | 1 }> = [];

         // 2. Interactive labeling of borderline or uncalibrated traces
         for (const trace of traces.slice(-15)) { // Review last 15 traces
           const answer = await ctx.ask({
             question: `Was action '${trace.action}' on '${trace.target}' aligned with intent? (y/n)`,
           });

           dataset.push({
             rawProb: trace.rawProbability,
             label: answer.trim().toLowerCase() === "y" ? 1 : 0,
           });
         }

         // 3. Fit new calibration curve using jevcal
         const fittedParams = jevcal.fit(dataset);

         // 4. Persist updated configuration for the primary guardrail plugin
         await fs.mkdir(path.dirname(configPath), { recursive: true });
         await fs.writeFile(configPath, JSON.stringify(fittedParams, null, 2));

         return `[JEV TUNING COMPLETE] Saved updated calibration parameters to .opencode/state/jevcal_config.json (Optimal threshold: ${fittedParams.optimalThreshold}).`;
       },
     },
   },
 };
};

async function getCalibratedThreshold(rawProb: number, projectDir: string): Promise<number> {
 try {
   const configRaw = await fs.readFile(`${projectDir}/.opencode/state/jevcal_config.json`, "utf-8");

1. Dual-Manifest Hierarchy
   * Project Schema Manifest (project_manifest.json): Persisted at the root (.opencode/state/project_manifest.json). Defines global project invariants, persistent non-goals, and immutable domain boundaries.
   * Call-Level Schema Manifest (call_manifest.json): Created or updated per prompt turn or task execution. Captures transient task objectives and localized file targets for the current action.
2. Supporting Role of OpenSpec
   * OpenSpec artifacts (spec.md, tasks.md) are appended to Jev's evaluation payload purely as supplementary context.
   * If a conflict occurs between an OpenSpec task statement and the project_manifest non-goals, the Primary Schema Manifest takes precedence, and Jev flags the evaluation as a violation.
3. Strict Meta-Tool Evaluation (No Whitelisting)
   * All meta-tool operations—including writes to .openspec/*, .opencode/*, or configuration files—are subjected to Jev trajectory evaluation.
   * If an agent attempts to edit spec.md or tasks.md in a way that shifts architectural constraints or breaks non-goals defined in project_manifest.json, Jev flags the tool call as intent drift (Palign​<0.80) and blocks execution.
Plugin Evaluation Logic (.opencode/plugins/jev-hierarchical-guardrail.ts)
import { Plugin } from "@opencode-ai/plugin";
import { JevClient } from "@typesafe/jev";
import * as fs from "fs/promises";
import * as path from "path";

const jev = new JevClient({ apiKey: process.env.JEV_API_KEY });

export const JevHierarchicalGuardrailPlugin: Plugin = async (ctx) => {
 const projectManifestPath = path.join(ctx.location.directory, ".opencode/state/project_manifest.json");

 return {
   // Intercept tool actions (both meta-tools and code edits)
   "tool.execute.before": async (input, output) => {
     // 1. Load Primary Intent Authorities
     const projectManifest = JSON.parse(await fs.readFile(projectManifestPath, "utf-8").catch(() => "{}"));
     const callManifest = await ctx.storage.get("call_manifest") || {};

     // 2. Load Supporting OpenSpec Context (if available)
     const specContext = await fs.readFile(path.join(ctx.location.directory, ".openspec/spec.md"), "utf-8").catch(() => "");

     const proposedAction = {
       tool: input.tool,
       args: output.args,
     };

     // 3. Evaluate Dual-Manifest Alignment via Jev
     const evalRes = await jev.evaluate({
       state: {
         primary_authority: {
           project_manifest: projectManifest,
           call_manifest: callManifest,
         },
         supporting_context: {
           openspec: specContext,
         },
         proposed_action: proposedAction,
       },
       questions: {
         aligns_hierarchical: {
           type: "Noul",
           statement: 
             "Does the proposed action (including edits to meta/spec files) strictly comply with call_manifest " +
             "WITHOUT violating any non-goals or invariants in project_manifest?",
         },
       },
     });

     const pAlign = evalRes.questions.aligns_hierarchical.probability;

     // 4. Decision Gates
     if (pAlign < 0.80) {
       throw new Error(
         `[INTENT DRIFT DETECTED] Tool action '${input.tool}' on '${JSON.stringify(output.args)}' ` +
         `violates Primary Schema Manifest constraints (P_align = ${(pAlign * 100).toFixed(1)}%).`
       );
     } else if (pAlign < 0.98) {
       const approved = await ctx.ask({
         question: `[BORDERLINE ACTION (${(pAlign * 100).toFixed(1)}%)] Approve '${input.tool}' on '${JSON.stringify(output.args)}'?`,
       });
       if (!approved) throw new Error("User rejected borderline action.");
     }
   },
 };
};

2. Pluggable OpenSpec Integration (@jev-guard/openspec-adapter)
To integrate with OpenSpec without tight coupling, an adapter binds OpenSpec's task lifecycle events to the core engine:
   1. Context Extraction: When an OpenSpec command or task starts (openspec run or task transition), the adapter reads .openspec/spec.md and active .openspec/tasks.md.
   2. Context Passing: The adapter injects the OpenSpec markdown into supportingContext.openspec while keeping project_manifest.json and call_manifest.json as the primary evaluation authority.
   3. Spec Integrity Check: When OpenSpec agent tools attempt to edit spec files, the adapter routes the edit through evaluateAction(). If the proposed spec change strays from project_manifest.json invariants, Jev blocks the write.
// @jev-guard/openspec-adapter
import { JevGuardEngine } from "@jev-guard/core";

export function createOpenSpecGuardMiddleware(engine: JevGuardEngine) {
 return async (openspecContext: any, next: Function) => {
   // 1. Read current OpenSpec state as supporting context
   const specDoc = await openspecContext.readSpec();
   const activeTask = await openspecContext.getActiveTask();

   // 2. Resolve Primary Call Manifest for current task
   const callManifest = {
     action_type: activeTask.type,
     target_scope: activeTask.scope,
     acceptance_criteria: activeTask.criteria
   };

   // 3. Attach engine evaluation to OpenSpec tool execution phase
   openspecContext.onToolExecute(async (action: any) => {
     const result = await engine.evaluateAction(
       action,
       { project: openspecContext.projectManifest, call: callManifest },
       { openspec: specDoc }
     );

     if (result.pAlign < 0.80) {
       throw new Error(`[OPENSPEC GUARD] Action violates Primary Schema Manifest.`);
     }
   });

   return next();
 };
}

With the core engine decoupled, host integrations become tiny wrapper plugins:

   * MCP Server (jev-mcp-server): Exposes @jev-guard/core as a standard Model Context Protocol stdio server for use in Claude Code, Cursor, or Goose.
